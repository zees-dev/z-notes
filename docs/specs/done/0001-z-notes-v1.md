# 0001 — z-notes v1 — the build-ready product spec

> Founding document, retrofitted into the spec template when the repo adopted
> the agent-first shape (ADR 0001 era). Archived here as a completed spec:
> staleness is harmless, durable decisions live in `docs/decisions/`.

## Problem Statement

A single-user markdown note-taking app whose files on disk are the source of truth, self-hosted on a private network, with client-side secrets, git sync, an AI edit relay and a gated terminal — buildable in phases with zero framework dependencies.

## Solution

One Bun process serving a no-build frontend and a versioned HTTP/SSE contract; sqlite as a rebuildable cache over the vault; every decision below in the numbered sections. "SPEC §N" anywhere in the codebase refers to section N here.

## User Stories

1. As the vault's owner, I want my notes to be plain `.md` files on disk, so that no app lock-in ever exists.
2. As the owner, I want edits from ANY tool (editor, git pull, this app) reconciled automatically, so that the app is a view, not a silo.
3. As the owner, I want secrets encrypted in my browser before they touch the server, so that the server never holds plaintext.
4. As the owner, I want every change committed and pushed automatically, so that history and backup are free.
5. As the owner, I want an AI assistant that can only PROPOSE edits I accept/revert LIFO, so that it can never destroy work.
6. As the owner, I want the terminal gated behind a password and per-command approval, so that AI-run commands are never autonomous.

## Implementation Decisions

The entire v1 design, verbatim (headings demoted one level). The numbered sections are the canonical "SPEC §N" references used across code comments and tests:

Single-user markdown note-tasking app. Files on disk are the source of truth; the app is a view over them.

---

### 1. Goals & principles

- **Markdown-first**: you write markdown; files are byte-faithful and always editable outside the app (vim, IDE). The app picks up external changes automatically.
- **Decoupled frontend**: the UI talks *only* to the versioned HTTP/SSE contract ([API.md](0002-http-api-v0.md), normative v0). New frontends or a mobile app reuse the backend unchanged.
- **Bun-only toolchain**: `bun install` / `bun build` / `bun test`; no npm, no node. Backend is one bun process. sqlite via `bun:sqlite`.
- **No data leakage**: secrets are encrypted client-side; plaintext never reaches disk, git, sqlite, logs, or the AI endpoint.

**Out of scope for v1** (map: Out of scope + fog): HTML/PDF export, native mobile/desktop apps, task rollups/queries (fog — pull in later if wanted), AI delete/rename powers.

### 2. Architecture

```
┌─ browser ──────────────────────────────────────────┐
│ frontend (static, themed)                          │
│   app.js ── api.js (ONLY network layer)            │
│   crypto Web Worker (age unlock, plaintext jail)   │
└───────────────┬────────────────────────────────────┘
                │ HTTPS  /api/* + /events (SSE)
┌───────────────┴────────────────────────────────────┐
│ bun backend (one process, k3s pod, auto TLS)       │
│   Bun.serve: API + static frontend                 │
│   watcher → debounce 120ms → reconcile → SSE       │
│   sqlite (WAL, FTS5): rebuildable index + creds    │
│   git runner (Bun.spawn argv) → GitHub             │
│   AI relay → /v1/responses (key server-side)       │
└────────────────────────────────────────────────────┘
```

- Backend: one entrypoint plus small modules under `server/` — `index.ts`, `vault.ts`, `watch.ts`, `git.ts`, `ai.ts`, `db.ts`. Dev: `bun --hot server/index.ts` (zero build); prod: `bun build` HTML entrypoint, optionally `--compile` single executable. ([Bun capabilities](0005-bun-platform-foundation.md))
- `Bun.serve` traps: `idleTimeout: 0` + ~20s heartbeat or SSE dies at 10s; `Bun.file` responses carry no ETag — add cache headers manually.
- macOS `fs.watch` is a contentless doorbell (eventType always "rename"; atomic saves name only the temp file): never trust the payload — debounce 120ms, then reconcile `Bun.Glob` → `stat` → `Bun.hash` against sqlite, emit `doc-changed` on real differences only.
- Git via `Bun.spawn` argv arrays (token never enters a shell string).

### 3. API contract

[API.md](0002-http-api-v0.md) is normative v0: docs CRUD with opaque `rev` + 409 conflicts, `POST /api/docs` (doc/folder create), `/api/search` (server-side fuzzy, match offsets), `/api/settings` (server-declared `meta` drives UI option lists), `/api/sync/status`, AI sessions/messages/proposals with server-enforced LIFO, `/events` SSE (`doc-changed`, `sync-status`, `heartbeat`).

**Deltas for the real backend** (mock conveniences to correct):

1. **Remove `POST /api/secrets/unlock`.** In the mock the server returns plaintext; in the real app decryption is client-side only (§6). The server has *no* secrets endpoint. `GET /api/vault/identity` serves the wrapped identity file instead.
2. Add `PATCH /api/docs/{path}` rename/move (rewrites backlinks server-side, one commit) and `DELETE /api/docs/{path}` (human-only, currently 501).
3. `PUT /api/docs/{path}` performs the rev check atomically; 409 returns the current server markdown so the client can raise the conflict banner (§5).
4. `POST /api/ai/messages` streams (SSE or chunked) rather than returning a blob.
5. Add `/api/terminal/*` (§13): status, unlock/lock, password, exec (SSE), stdin, cancel, and the assistant's command records. Every mutating route is inside the existing `/api/*` cross-site guard; every route except `status` needs the terminal bearer.

### 4. Editor

- **Two modes**: Preview (rendered, **default**) and Raw (exact markdown source, monospace). Toggle: `⌘E`, or the **mode chip in the statusbar**. The chip is one muted word — `Preview` / `Raw` — carrying the same size and weight as the line and word counts beside it, and its `title` says both what a click does and the chord. It is **not** topbar chrome: which of two views of the same document you are looking at is *state*, and the statusbar is where this app says state; a 100px two-button segmented control was more furniture than the fact deserved. `#stMode`'s `data-mode` attribute is the contract everything else addresses it by (`syncModeUI`, the tests). It is never shed at any width — below 768px there is no `⌘E`, so the chip is the only way to reach Raw on a phone — and it is hidden on the settings route with the topbar's other document controls, because it acts on a document that is not on screen. Preview is still the mode a doc opens in. Lossless by construction — the source string itself is edited. Raw surface: CodeMirror 6 or a plain textarea (prototype proves textarea suffices); no TipTap, no AST bridge.
- **Container parity**: both modes share the identical container (borders, padding, max-width, scroll). Only the text changes. Scroll position preserved across switches.
- **Click zones**: click in Preview body → Raw with caret on the corresponding source line. Exceptions: task checkboxes toggle in place (rewriting their `- [ ]` line), `[[links]]` navigate, secret-block and code-copy controls act, selection drags don't switch. Click the pane whitespace outside the doc while in Raw → back to Preview. Blur never switches modes.
- **Leaving Raw never silently discards a staged buffer.** If the current source differs byte-for-byte from the last server-confirmed document, every exit funnel — `Esc`, `⌘E`, the statusbar mode chip, pane-whitespace click, another doc, Settings, browser Back, or confirming deletion of the active doc/folder — raises one confirmation modal before leaving. Its diff contains only added and removed lines from that saved baseline, not the full document or unchanged context. **Keep editing** returns to Raw untouched; **Exit without saving** restores the confirmed bytes and continues to Preview/the requested destination; **Save & exit** continues only after the write lands. With no diff, `Esc` leaves Raw directly for Preview.
- **Preview rendering**: h1–h3, paragraphs, bullet/task lists, fenced code (highlighted), tables, quotes, dividers, `[[slug]]` pills. A ` ```age ` fence renders as a secret block, never as code: locked it shows a masked body with **no ciphertext at all**, unlocked it shows the plaintext (§6). Raw is where a secret block's source lives — it is the byte-faithful view of the file, armor included, and that is deliberately the only place in the app the armor appears. **Blank-line multiplicity is preserved**: each blank line beyond the first between blocks adds one body line-height of space.
- **Fenced code blocks wrap; they never scroll sideways.** A long line is content, not a reason to hide the rest of the block behind a horizontal scrollbar, so the rendered `<pre>` is `pre-wrap` with `overflow-x: hidden` — every space and tab of the source survives, and a break lands inside a token only when that token alone cannot fit the column. Each source line is its own block box carrying a hanging indent, so the continuations of a wrapped line sit one step in and stay distinguishable from the next real line; the newline stays inside that box, so the block's `textContent` is still the source verbatim. The header bar carries the language label and the copy control and nothing else — the three decorative "traffic light" dots are gone, they meant nothing and readers tried to read them. Bar height, code size, leading and padding all scale with density (`--d-code-*`, `--d-pre-*`), so Compact is genuinely tighter than Comfy rather than the same block in a smaller font. **Raw mode is untouched**: it is the byte-faithful source surface, and the §11 parity gate still measures container equality between the modes.
- **Saving**: autosave debounce (default 10s, configurable), manual save button, `⌘S`. Save sends `{markdown, rev}`; statusbar shows saved/dirty state.
- **The buffer is flushed at every boundary the page has, not just at `pagehide`.** The debounce is a `setTimeout`, and a frozen page runs no timers — iOS freezes a backgrounded tab at `visibilitychange` and may discard it without ever firing `pagehide`, so up to a full debounce of typing had no path to disk at all (measured: the canary text was not in the file after `hidden`, and was after `pagehide`). `visibilitychange → hidden` therefore runs exactly what `pagehide` runs: sync the raw buffer, then a silent `keepalive` save. The debounce stays at 10s — shortening it would be a worse fix for the same problem, since a frozen page cannot run a shorter timer either. A body over the browser's ~64KiB `keepalive` allowance is sent **without** `keepalive` rather than being rejected outright, because a rejected flush is silent loss proportional to how much was written. The mirror runs on the way back in: `visibilitychange → visible` and the `online` event reconnect the stream if it is not open, **retry the write**, and re-read the tree and the open doc. The retry is not optional: `doSaveDoc` clears the debounce *before* it attempts the `PUT` and only a keystroke re-arms it, so a save that failed while the network was down was the last attempt ever made — measured, the chip read "connected" beside an indicator reading "Unsaved changes" and the text was still not on disk 7.5× the debounce later. The heal's re-read deliberately cannot cover it (it returns immediately on a dirty buffer, so it can never clobber typing), and the flush is a no-op on a clean one. The returning flush is **not** `quiet`, unlike the leaving one: a page that is staying is exactly where the orphan veil, and a failure, have somebody to talk to.

### 5. Data model, links, external edits

- A doc = any `.md` under the vault root; `.znotes/` excluded. Full IDE-parity file ops from the sidebar (create inline-named, rename, move, delete — destructive ops human-only, confirmed). Reachable three ways, all driving the same inline editor and the same confirm: the footer buttons + `⌘N`/`⇧⌘N`, the per-row hover actions + `F2`/`Del`, and a **context menu** (right-click, `⇧F10`/Menu with focus in the panel, or a **500ms long press** on a row). The menu carries an explicit PLACEMENT — the folder it was opened on, or the vault root on empty space. The long press is not a fourth surface, it is the same menu from the same `ctxTarget`: without it a phone had *no* route to rename, move or delete a **file**, because the hover actions are revealed by `:hover`/`:focus-within` and tapping a file row runs `openDoc`, which closes the drawer and takes the row and its actions off-canvas — reopening it moves focus to the Menu button, so the reveal is lost again (measured at 390×844: an unbreakable loop; folders escaped it only because their row toggles disclosure instead). It cancels on a 10px drag or a tree scroll, so a flick down the list is still a scroll, and it swallows exactly one trailing tap: a touch not consumed by `contextmenu` still emits compat `mousedown`→`click` at liftoff, which would otherwise close the menu on the gesture that opened it and open the doc underneath.
- **Creation is context-aware and path-aware.** `⌘N` (doc) and `⇧⌘N` (folder) create *relative to what you are looking at*: the sidebar folder last clicked or focused → inside it; a doc row clicked/focused, or simply the open doc → its parent folder; nothing picked and nothing open → the vault root. Both gestures resolve the context identically, and every ancestor of it is expanded before the inline row mounts so the input is never buried in a collapsed subtree. The **input takes a path**, relative to that context: `abc` → `abc.md`, `a/b/c.md` → folders `a` and `a/b` then the doc, `abc/` → the **folder** `abc` (a trailing slash always means folder, in either mode — the only override the grammar has), a leading `/` re-bases on the vault root. A bare name gets `.md` because a doc *is* a `.md` file here, so `notes` can only mean `notes.md`. **The field explains nothing** — no hint line, no grammar in the placeholder: the second line under the input is mounted only to carry a *refusal* (a path the client rejects, or the server's `409`), which holds the row open with the typed name still in it.
- **Creation never clobbers and never half-lands.** A duplicate doc or folder is refused (`409 exists`) and the refusal is surfaced *in the create row* with the typed path still in the field — not swallowed into a toast. So is an intermediate segment that is an existing file (`readme.md/x.md`), a name carrying `]` or a line break (it could not survive the `[[link]]` a later rename would splice it into — the same guard `PATCH` applies to its destinations), a dot-prefixed segment, and anything `safePath` rejects. Server-side the implicit parent folders are rolled back (`rmdir`, so a folder with anything in it survives) if the create they were made for fails.
- `[[slug]]` resolves by unique filename slug vault-wide; `[[path/slug]]` on collision. Rename/move rewrites all backlinks in one commit. Broken links render flagged with create-doc affordance.
- External edits: buffer clean → silent reload + "updated from disk" blip; buffer dirty → conflict banner with diff, take-disk / keep-mine. Multi-device concurrency uses the same rev + SSE machinery.
- **A deletion never takes an unsaved buffer with it.** A doc removed elsewhere — another client's `DELETE`, a `git pull`, an `rm` — used to drop the cache entry unconditionally, which made the next `⌘S` a *silent no-op*: no request, no dialog, no toast, and the indicator reading "Unsaved changes" forever over text that had nowhere left to go (measured: ~1000 characters, with a 1.9s toast as their only trace). A **dirty** buffer now survives the file's removal as an **orphan** — still on screen, still editable — and the next save raises the same veil the conflict banner uses, with **Recreate** (a `POST /api/docs` carrying the buffer) and **Discard**. A `404` from a `PUT` is the second way in, for the case where the announcement was missed. Recreate is always an explicit button: resurrecting a doc somebody deliberately deleted on another device would be the same silent decision in the other direction — and a button is **not** explicit while it is holding focus under a caret, because the space bar presses it. The veil is raised by the ordinary autosave as well as by `⌘S`, so it only *moves* focus for a save the user asked for; raised unprompted it focuses itself and leaves no default verb under the next keystroke. (Measured at the shipped 10s debounce: a pause to think opened the veil, the resumed sentence's first space recreated the file and the following 26 characters went into the button — both failures this dialog exists to prevent, on one keystroke.) Clean orphans still evaporate. The notice for a deletion or a move under an unsaved buffer is **sticky** — the user may be mid-sentence, and 1.9s is a lie about something that changed what `⌘S` will do — while the "updated from disk" blip stays a blip.
- **Delete is recoverable by default.** `DELETE /api/docs/{path}` moves the exact doc bytes — or a folder and its whole payload — under `.znotes/trash/<id>/` instead of unlinking them. The active pane opens the next doc down in the current tree hierarchy (else the previous neighbour, then the nearest parent neighbour). A quiet **Recently deleted** disclosure sits between the tree and New doc / Folder, lists every retained entry, and offers Restore or confirmed permanent deletion. Restore returns the bytes to their original path and recreates every missing ancestor directory; it refuses rather than overwriting a new occupant. Retention defaults to **7 days**, is configurable as `trash.retentionDays` in Settings, and is enforced at boot, after deletes, when the setting changes, and by the scheduled sweep.
- sqlite (`.znotes/index.db`, untracked, WAL): doc index (path, rev, hash, mtime), FTS5 search, backlinks graph, AI chat history, proposal pre-images, credentials. Fully rebuildable except credentials/history; deleting it never loses notes.
- **A corrupt index is PARKED, never deleted.** The tree, FTS and backlinks all rebuild from the markdown, but the GitHub token, the AI key, the terminal password hash and the whole proposal undo stack live here and nowhere else *by design* — so `rmSync` at boot threw four unrecoverable things away, silently, to fix a cache. The file is renamed to `.znotes/index.db.corrupt-<ts>` instead (the shape `identity.age.prev` already establishes), with its sidecars as `…corrupt-<ts>-wal` / `-shm` so the parked set is still a valid sqlite triple and the WAL — which can hold the most recent credential write — sits where `sqlite3 .recover` will find it. Each rename is individually guarded: the sidecars are simply absent after a clean shutdown, and a boot must not fail because of that. Recovery is manual and deliberate; what boot owes the user is only to not make it impossible.

### 6. Secrets

(full params in [secrets-crypto.md](0004-secrets-client-side-crypto.md))

- **age-in-a-fence**: standard age v1 PEM armor inside a ` ```age ` fence, via the `age-encryption` (typage) library. Per-block X25519 encryption to the committed vault recipient (`.znotes/vault.pub`); the identity lives in `.znotes/identity.age`, passphrase-wrapped with scrypt logN=18 (r=8, p=1).
- One passphrase unlock per session, inside a dedicated **crypto Web Worker**; key held as a non-extractable CryptoKey; nothing in sessionStorage; auto-lock timeout. New blocks encryptable while locked (recipient is public).
- Leak rule is structural: autosave, indexer, server, git, and AI context all read stored markdown = armor only. Client-side AST redaction + `BEGIN AGE ENCRYPTED FILE` canary filter on the AI relay as belt-and-braces.
- **The LOCKED block shows NO ciphertext.** A locked block is the padlock, the `age · x25519 · encrypted` descriptor, the LOCKED badge, the Unlock button, and a masked body: a fixed row of blanks that is obviously not content. Not the armor, not its `-----BEGIN AGE ENCRYPTED FILE-----` header, not a line or byte count — the size of a secret is data about the secret, and the mask's width and count are constants so nothing about it tracks the payload. It carries no text node at all, so neither `innerText` nor `textContent` yields a byte of the block. Dumping the base64 body inline was the original bug (a correctly-encrypted block read as an exposed one: what a reader saw was several hundred bytes of ciphertext, not the badge above it), and putting it behind a disclosure only moved it one stray click away in a pane that invites you to click a line. **Raw mode (`⌘E`) is the escape hatch** and the only way to see a block's source in the app; it is byte-faithful by definition. Purely a *rendering* choice — the document model still holds the fence body verbatim, so an unedited unlock→lock→save is byte-identical (§11, `tests/secrets-e2e.test.ts`). The **revealed** state is unchanged (plaintext in an editor carrying every anti-exfiltration attribute), and so is the **flagged** state — with one deliberate exception: a fence whose body is *not* armor is shown in FULL, because those bytes are plaintext on disk and in git, and masking them would conceal exactly what the warning is about.
- **Reveal is VAULT-WIDE, not per block.** The vault has two states and the whole app reads the same one. While the worker holds no identity, every age block everywhere is a locked chip. The moment it holds one, every block in the doc on screen decrypts to plaintext with no further clicks — and so does every block in every doc opened afterwards, for as long as the vault stays open. A block's **Unlock** button is the *entry point* into that single state (click → passphrase modal → the vault opens → everything reveals), not a per-block permission: a passphrase already given is not asked for again block by block, and a doc of eight secrets is not eight clicks. Decryption is per block and asynchronous, so a block awaiting its worker round trip shows an `Unlocking` chip over the same mask — never a locked chip that flips a frame later. **Locking reverses it completely and everywhere**: manual Lock (the block's Lock button locks the *vault*), the idle timeout, the tab-hidden timeout, the hard session cap and another tab's BroadcastChannel signal all return every block to the locked chip, wipe every plaintext from the DOM, clear the clipboard, and cancel decrypts still in flight so a late answer cannot paint plaintext into a closed vault. **The wipe happens first, before any network.** An edited block still has to be re-encrypted and saved on the way out, and both of those are round trips that can hang — a wedged or suspended server used to hold the whole lock open, leaving the plaintext in an open editor indefinitely at exactly the moment the screen is unattended. The dirty reveals are snapshotted, the screen goes blank synchronously, and the ciphertext is written from the snapshot afterwards. A block that fails — malformed, truncated, MAC failure, wrong recipient, or a damage age cannot classify at all — keeps its own flagged, sticky classification instead of revealing, and one bad block never stops the others in the doc. **Every** failure is recorded, classified or not: an unrecognised one that recorded nothing was asked again by the next repaint, and again by the one that repaint caused — an unbounded retry loop under a block stuck on `Unlocking` with no way out of it.
- **Auto-reveal is DISPLAY ONLY.** Revealed plaintext lives in one in-memory map keyed by `path + which copy of the armor this is + armor`, scoped to the doc on screen; the document model holds the armor verbatim throughout. Ciphertext alone is not an identity — copy a fence to make a staging/prod pair and one document holds the same bytes twice, which made the two blocks share one reveal entry and one re-encrypt target, so an edit to either rewrote the *first* fence and destroyed the other's content under a "Saved to disk" toast. The copy index is what tells them apart, in the map, in the live nodes and in the re-encrypt that rewrites the *n*-th fence rather than the first one `indexOf` finds. A re-encrypt that lands while the pane is in **Raw** also pushes the new model back into the raw buffer, because that buffer is otherwise pushed *back over* the document on the next mode switch — which reverted the just-saved edit on disk. Opening a doc with the vault unlocked and saving it without editing leaves the file byte-identical, and autosave firing while blocks are revealed still sends armor only (§11 leak canary). Only a block whose plaintext was actually *edited* is re-encrypted on save. Nothing about the unlocked state is persisted to web storage.
- **Degradation**: no secure context → secrets features disabled (blocks stay locked and masked like any other locked block, badge explains why, and the armor is still in the document — masked, never dropped); everything else works.
- **A half keyring is a state, not a lie.** The two keyring files are written by two renames and can be pulled, checked out or tidied independently, so each one alone is reachable and each one is reported as itself. `identity.age` without `vault.pub` is **repairable**: the passphrase opens the identity and unlocking rewrites the missing recipient. `vault.pub` without `identity.age` is the mirror, and it is the state `writeVaultKeys` calls unrecoverable data-loss-by-encryption — the public half is enough to *encrypt*, so every block written there would be one nobody can ever open. It is never reported as a healthy vault: the keyring line says which file is missing and names `.znotes/identity.age.prev` (where an interrupted passphrase change parks the old key), blocks offer neither Unlock nor Create, and `⌃⇧E` refuses. Inferring either file from the other is what produced the old dead end — a status line naming a file nobody had looked for, an Unlock saying "no identity yet", and a Create the server answered with `409 exists`.
- **The generated passphrase is legible.** `Generate` fills the field and *unmasks* it, because "write it down NOW — nothing here can show it to you again" printed over `-webkit-text-security: disc` is an instruction that cannot be followed, and there is no recovery path to fall back on. Typing into the field masks it again, and the value leaves the DOM on success or on leaving the page — as does anything typed into the three passphrase fields, whether the attempt succeeded, was refused or threw. The settings page is a route change and is never unmounted, so leaving it is the only "close" those fields have.
- Recovery independent of the app: `age -d -i <(age -d .znotes/identity.age) block.age`.
- **Change passphrase** (Settings › Secrets; research §5.3, the "routine" of its two operations): the crypto worker unwraps `identity.age` with the current passphrase and re-wraps the *same* identity under the new one (fresh scrypt salt, logN=18), then `PUT /api/vault/identity {replace:true}`. The vault key does not change, so `vault.pub` is untouched, no block is re-encrypted, and everything already in the corpus still decrypts. Same entropy floor as first-run, same generator. Key **rotation** — a new identity plus a decrypt-and-re-encrypt pass over every block — is a separate corpus-wide operation and is deliberately **not** offered in Settings; the UI says so, and says that older copies of `identity.age` in git history stay decryptable with the **old** passphrase.
- **Where a secret lives — and why this panel's two password fields answer that oppositely.** The vault passphrase is **never stored**: not in sqlite, not in `.znotes/settings.toml`, not in `sessionStorage`, and it never reaches the server. What the backend holds is the passphrase-**wrapped** identity (`.znotes/identity.age`) plus the public recipient (`.znotes/vault.pub`), both committed with the vault — the server is a courier for two opaque strings and validates their shape only, which is what lets it never see a passphrase or a plaintext. The **terminal password** (§13) is the opposite by necessity: the *server* must verify that one, so it stores a scrypt **hash** of it and checks what is typed against it. Neither is recoverable; only the terminal one is checkable. Settings › Secrets states this next to the control.

### 7. Git sync

- Debounced auto-sync: 60s (configurable) after saves settle → `git add` changed notes → commit (auto message: timestamp + files touched) → push to configured branch (default `main`). Manual "Sync now" always available.
- Push rejected → `pull --rebase` → retry. Real conflict → editing continues, statusbar goes to error state, conflict UI for manual resolution; the app never auto-destroys either side.
- Two canaries stop the pipeline before `add` rather than committing something that cannot be taken back: a credential hand-written into `settings.toml`, and a **half-replaced keyring** — `.znotes/identity.age.prev` present while `.znotes/identity.age` is gone, which is exactly where a crash inside `writeVaultKeys` lands. The stash is deliberately never committed (it is local crash recovery), so committing the *deletion* beside it would lose the key on every other clone; sync stops and says which file to rename back.
- Committed: notes, `.znotes/settings.toml`, `.znotes/vault.pub`, `.znotes/identity.age`. Ignored: `.znotes/index.db`, `.znotes/index.db.corrupt-*` (a parked corrupt index is a *copy of the credential store*, so this is a secrecy rule, not a tidiness one), `.znotes/identity.age.prev`. Credentials (GitHub token, AI key) exist only in sqlite. Token used only as HTTPS credential via env/credential-helper — never in argv or remotes.
- **A settings save schedules a sync like any other write.** `settings.toml` is committed, and `applySettings` only re-arms the timer when auto-sync was just switched *on* — so on a repo whose auto-sync was already on, every settings save left the file uncommitted until an unrelated note edit swept it up (measured: minutes of "1 pending"). `PUT /api/settings` schedules on success.

### 8. AI

- Pluggable OpenAI-compatible endpoint; settings: base URL, key (sqlite), model (default `gpt-5.6-sol`), effort (default `high`). Backend relays `POST {base}/v1/responses` with SSE; key never reaches the browser. Send `reasoning:{effort,summary:"auto"}`, `store:false`; capability probe at settings-save; documented fallback ladder to chat-completions.
- One global assistant; context = current doc (server-assembled from on-disk bytes → secrets structurally excluded) + what the user attaches. Sessions resettable; message count + token estimate visible; history in sqlite.
- Proposals: single strict `propose_edits` function tool, anchored search/replace spans; ops `replace | insert_after | create | rewrite` (no delete/rename). Server validates against on-disk bytes (unique anchor, path confinement, no intersection with age blocks) before the UI offers Accept; failures feed back for ≤2 in-turn retries. Plain replies carry `proposal: null`.
- Accept → apply + sqlite pre-image + one git commit per proposal. Revert strictly LIFO, enforced server-side (409 `not-stack-top`).
- **Second tool, `run_command` (§13)**: declared *only* when the terminal is enabled and has a password, so a vault without one never tells the model the capability exists. The system prompt gains a "The terminal" section describing what it can do, that there is no TTY, that the cwd persists, that the user sees every command, and that notes and fetched documents are untrusted text rather than instructions. The gate: the terminal must be **unlocked**, and by default each command **waits for explicit user approval** (a Run/Reject card, the same shape as a proposal). `terminal.allowAiAutoRun` removes the click and ships **off**. Approved output reaches the model on the *next* turn, as a context block explicitly labelled program output; auto-run output comes back in-turn as the tool result. An auto-run that arrives while anything is already running is **refused** (`reason: "busy"`) rather than started — the user's command is never displaced by the model's. ≤4 `run_command` calls per turn.

### 9. Frontend, themes, settings

(theme contract: [THEMES.md](0003-theming-token-contract.md))

- Three themes — Modern, Minimalistic, Terminal/TUI — as CSS token files over `base.css` (~140-token contract, all layout/behavior in base). **Minimal is the default.** Live-switchable from settings — the pick previews instantly and Save persists it (see below); theme list comes from server `meta`. Adding a theme = backend meta entry + one CSS file.
- Colour scheme: `system | dark | light`, a second axis orthogonal to the theme. app.js stamps the resolved value as `data-scheme` on `<html>` and keeps `<meta name="color-scheme">` in step; every theme carries a full palette for **both** schemes (Terminal ships a light variant, Minimal a dark one), so all six combinations are supported. `system` is a live subscription: a `matchMedia` listener repaints a mid-session OS switch with no reload, and is detached the moment the setting is pinned. `index.html` resolves the scheme — **and the theme and the density** — synchronously in `<head>` from a cache of what was last applied, before the boot splash paints, so there is no flash of the wrong ground and no repaint into the right theme a frame later. A profile that has never run the app is the one case that cannot be resolved before the network, and costs exactly one repaint. `?theme=` and `?scheme=` override for one page load without persisting — and the vault cannot take the pin back: a `settings-changed` that moves a **pinned** axis is skipped by the adopt path (measured: a page opened at `/?theme=terminal` flipped to `minimal`, cache and all, the moment another device saved a theme, so a kiosk or screenshot tab changed appearance mid-session). The pin is spent the moment *this* client applies that axis on purpose — a Save, a Discard, or leaving Settings with a drafted look — because that is the user answering the question the URL pre-answered.
- Density: **Comfy default**, Compact tighter; both via CSS variables. The scale sits one rung denser than it did — the old Compact is the current Comfy, and Compact is a new rung below it — floored at `--d-ctl-h` ≥ 22px / `--d-row-h` ≥ 17px so hit targets survive.
- **Responsive: one axis (WIDTH), four bands, and a measure floor.** There are deliberately no `pointer:` queries — an iPad with a keyboard and an iPad without one are the same layout problem, and a second axis answers it twice. The rule the bands exist to keep: **no persistent column may take the document's measure below 45 characters** (~520px at the body size, the unit the shell does its arithmetic in since it cannot know a theme's font); where the viewport itself cannot afford that, the document gets all of it, which is the most that exists. It is a floor, not a target — Terminal caps at `--doc-max-w: 84ch` and settles at ~499px in Compact, which is the 84 characters that theme is deliberately asking for. Transient dismissible layers — the sidebar drawer, the chat overlay — may cover the document, because covering is undone by one tap and does not survive a reload; a column is neither. That rule plus the widest sidebar (262px), the widest chat (352px) and the document's own gutters gives the three breakpoints, which `base.css` §11 and `app.js` (`W_SHEET` / `W_DOCK` / `W_TRIPANE`) state as the same three numbers:
  - **<768px — phone**: sidebar drawer, chat **bottom sheet**, document full width.
  - **768–1023px — tablet**: sidebar still a drawer, chat a right-hand **overlay**, document full width.
  - **1024–1279px — small laptop**: sidebar returns as a **column**, chat still an overlay.
  - **≥1280px — desktop**: the classic **three panes**, chat as a column.
  
  The previous rule made 768px the *only* breakpoint, so every tablet landed in the three-pane desktop grid with the assistant open: measured, a 768px window gave a **172px document column and ~120px of text**, 820px gave 224px, 1024px gave 428px — and because nothing remembered that you had closed the panel, every reload landed there again. **The assistant's open/closed choice is now remembered** (`znotes.chat`, the same pre-paint cache idiom as theme/density/scheme) and honoured at every width; with nothing remembered it opens only where it is a column. `⌘B` follows the same fork — it toggles the drawer below 1024px and collapses the column above it, rather than toggling a class nothing reads. A dismissed off-canvas panel stops accepting input on the same tick the class changes (`pointer-events`), not when its slide finishes.
- **The statusbar sheds by its own width, not the window's.** It lives *inside* the document pane, so its width is the window minus the sidebar minus the chat column — a different number from the one its `max-width` ladder was written in. Measured: at a 768px viewport the bar was 172px wide with 222px of content while every `max-width: 1019px` rule was still dormant, and `overflow: hidden` amputated its right-hand end, taking `#stConn` with it. The ladder is a **container query** on the bar itself, at the widths the old viewport thresholds used to produce, so it fires for a narrow window, an open chat column and a collapsed sidebar alike and cannot drift from the shell's layout again.
- **The assistant on a phone.** The sheet is 440px, not 640px, and raises **no scrim**: the document above it stays visible, scrollable and clickable, which is the whole point of asking a question about it (measured before: the sheet took 76% of a 390×844 screen and `elementFromPoint` returned `#scrim` over every remaining pixel). Below 768px **`⏎` inserts a newline and Send is the only way to send** — a phone keyboard has no `⇧⏎` to offer, so the desktop binding made a multi-line prompt impossible to type — and Send is a 44px target with a hint that says so. One `visualViewport` resize listener publishes the soft keyboard's overlap as `--kb`, applied to the shared `.doc` container and the chat panel and **never** to `#rawArea` (that would be exactly the mode-parity break §11 guards, and a headless gate cannot catch it). The sheet's grab handle is **gone**: it was a `::before` pill with no drag handler anywhere, and the sheet already carries a labelled close button.
- **No focusable text field is under 16px on a phone.** Mobile Safari zooms the viewport in when a field smaller than 16px takes focus and does **not** zoom back out when it blurs, so every band, floor and ladder above is discarded by the first tap into a field and the user is left panning a layout that was computed for a viewport they can no longer see. Below 768px every field the user types into — the raw editor, the chat composer, the search palette, the settings inputs, the terminal line, the secret editor, the sidebar's create/rename row — is floored at 16px. It is a **floor and not a size**: it applies only below the breakpoint, and `--d-raw-fs` and the density tokens still drive all of them everywhere else. Three things it is deliberately **not**: it is not a `:root` token override (the theme sheets link after `base.css` and redeclare those tokens at equal specificity, so a token override inside a media query is inert — the same trap that had the phone drawer shipping the theme's 252px instead of its own width), it is not a bare `.inp` rule (all 25 of them are `class="inp mono"` and `.inp.mono` outweighs it), and it is not written where the rest of the phone band is (`.term-in` declares its 12px *below* that band, so a rule placed there is dead text). The one row built for 12px that now holds a 16px field — the sidebar's create/rename row — is allowed to be as tall as its contents on a phone; `--d-row-h` itself is untouched, so the density floors above still read the number they always did.
- Shortcuts: `⌘E` mode, `⌘S` save, `⌘K`/`⌘P` fuzzy search palette, `⌘N`/`⇧⌘N` new doc/folder, `⌘/` **or** `⌘,` settings, `⌘J` **or** `⌘C` chat panel, `⌘B` sidebar, `⇧⌘E` encrypt selection, `⇧⌘L` lock vault, `⇧F10` sidebar context menu (`↑`/`↓`/`Home`/`End`/`⏎` inside it), `Esc` dismisses topmost layer, `?` shortcuts overlay. Statusbar: doc path, live line count, **editor mode** (the chip of §4), sync state, shortcut hints, SSE connection dot (auto-reconnect with backoff).
- **The connection dot reports what it can observe, and a heartbeat that is missed is acted on.** `EventSource.readyState` is not liveness: a stream can stop delivering without ever closing — a Wi-Fi→cellular NAT rebind is the ordinary way — and it was measured staying `1` for 75 seconds with `onerror` never firing, the chip reading "connected", and the pane showing a document superseded 75 seconds earlier. The server's 20s heartbeat is what makes this answerable, so it stops being a 900ms blink: every frame on the stream stamps a timestamp, and silence past **2.5 heartbeat intervals** (50s — wide enough that raising the server interval cannot make the chip flap) forces a reconnect, after which the existing `hello` → `epoch` gap-check recovers the content. The dot is painted from that same clock rather than from `readyState`, so "connected" is a claim the client can actually support and an open-but-silent stream gets its own word — and it gets a **watchdog tick to itself**, because painting "no signal" and reconnecting in the same task renders neither. **The same clock watches a reconnect that never lands.** An `EventSource` whose request went into the hole sits at `readyState 0` indefinitely — `onerror` never fires, so it never closes and the close-driven backoff never arms; measured against a NAT rebind, exactly *one* `GET /events` was ever issued and the chip read "reconnecting…" over a superseded document even after the network was fully healed (Chrome makes it near-certain by reusing a pooled keep-alive socket, which the rebind killed too). So a `connecting` handle silent past the same threshold is retried as well, and **every** watchdog-initiated retry walks the same 1→2→4→15s backoff a close does, so a genuinely dead network is not stormed with an attempt every 5s. The reconnect is deliberately **not** gated on a liveness probe: a `fetch` issued inside the same black hole hangs for its full connect timeout and makes recovery *slower* (measured: 48s → 63s).
- **Two chords have a second owner, and each is resolved in its favour.** `⌘/` and `⌘,` are both Settings, because `⌘,` is a decade of macOS muscle memory and `⌘/` is what every app that is not a Mac app uses; dropping either to have one canonical chord would be a regression for half the people who type it. `⌘C` is different in kind: it is **COPY**, and the chat toggle only gets it when the copy it would shadow is provably a no-op — nothing selected anywhere on the page (`window.getSelection()` collapsed or empty) *and* focus outside every text surface (raw editor, chat composer, search palette, settings fields, the terminal line). In every other case the handler returns **without** `preventDefault`, so the browser's own copy runs untouched; `⌘⇧C`/`⌥⌘C` are never intercepted at all. The guard tests the selection *and* the focus, not either alone: an empty search box has nothing to copy but `⌘C` there is still the field's key. `⌘J` remains the unconditional toggle, so there is always one chord that does not have to reason about focus. The terminal's own `Ctrl+C` cancel is untouched — it lives on `#termInput`, stops propagation, and sits behind the focus guard regardless.
- **Routing — one URL per place the pane can be.** `/d/<vault path>` is the open doc (each segment percent-encoded; the `/d/` prefix is what keeps it collision-free against `/api/*`, `/events`, `/vendor/*`, `/healthz` and every real file under `app/`). `/settings` and `/settings/<section>` are the settings **page** — `appearance | editing | git | secrets | ai | terminal`, so "open Settings at the AI group" (what the statusbar AI chip does) is a link anyone can follow. The server answers both prefixes with the SPA shell, byte-identically to `/`. Both are deep-linkable, reloadable and walkable: entering Settings pushes one entry, `Back` returns to the doc you were reading and `Forward` comes back. Leaving by the **Back button** in the settings header spends an entry that already exists rather than making one — the entry underneath when arriving pushed onto it, the entry ahead when you walked *back* onto this one — so the round trip leaves the stack the size it found it and truncates nothing. Only when there is neither (a deep link or a reload: Settings *is* the entry the browser handed us) does it navigate. It never walks below that first entry: underneath it is another site, not this app. What is deliberately **not** in the URL: the editor mode (`⌘E` is how you look at a doc, not which doc) and — one level down — the settings section when you are already on the page, so the section rail replaces the entry rather than stacking six scroll positions. Exactly three writers touch `history`: the doc funnel, the settings funnel, and the one observer that pushes an overlay's dismissal marker.
- **Settings is a page, not a modal.** It replaces the editor pane's content — sidebar, topbar and statusbar keep their places, so the tree stays available to navigate away with and the AI chip that links *into* Settings does not vanish on arrival. One entry point (`openSettings`), reached from the labelled row at the **bottom of the sidebar** (below New doc / Folder, mirroring the search button at the top: icon · label · `⌘/`; the row prints `⌘/` and its title names `⌘,` as well, because two `<kbd>`s would out-width the rhythm), from `⌘/` **or** `⌘,`, and from the AI chip; there is no topbar gear — an unlabelled glyph beside a labelled row is two mechanisms for one route. The document controls are hidden while it is up: Save, the save indicator and the crumbs in the topbar, and the mode chip in the **statusbar** — on a page with no document they would be live controls acting on something you cannot see. The statusbar items that remain are facts about the doc you were reading, not controls acting on it. **`Esc` does nothing there** — a page is not a layer to dismiss; leaving is `Back`, the header's Back button, or opening any doc. Arriving also stands down whatever is lying across the pane: the sidebar drawer below 1024px, and the assistant below 1280px — at those widths it is an overlay or a sheet, and it would otherwise cover the page it just navigated to. The draft survives (that collapse is CSS, not an unmount) and it does **not** rewrite the remembered open/closed choice: a detour through Settings is not the user deciding they are done with the assistant.
- **Settings BUFFERS, and Save is a real button.** Every control on the page used to `PUT` on its own keystroke, which left the header button with nothing to do but navigate while wearing the word "Done". The page is a **form** now: a control writes a local **draft** (a flat map of dotted path → pending value), and **Save** is enabled exactly when that map is non-empty — so setting a control back to the value the server has *deletes* the entry and the button goes inert again, without a "something was touched" flag anywhere. Save issues **one** `PUT` carrying **exactly** the keys that moved (nothing the user never touched rides along, so two tabs editing different sections cannot clobber each other), takes the server's answer as the new baseline — it clamps, snaps and trims — and live-applies from there: the crypto worker's auto-lock policy, the autosave debounce, the AI chip's model and effort, the vault button's home doc, and the terminal's server-side verdict, all with **no reload**. A refused value is reported with the server's typed code (`bad-base-url`, `bad-branch`, `unknown-theme`, …) **next to the field that caused it**, and the draft stays dirty because nothing was saved. **Discard** is offered only while there is a draft.
- **Settings reach the other client.** A successful `PUT` broadcasts `settings-changed` on `/events` carrying the same masked body `GET` serves, so a tab left open all day stops painting *and enforcing* a theme, home doc, autosave interval or auto-lock policy that was changed hours ago somewhere else; a reconnecting client re-reads them in the same once-per-connection block it re-reads the AI status in (settings do not move the vault epoch, so the epoch gap-check can never cover them). Only the paths whose stored value actually **moved** are applied — re-applying an unchanged appearance axis would stamp the stored value over a `?theme=` / `?scheme=` URL override — which also makes the saving client's own echo a no-op. A client holding an unsaved draft repaints everything but applies nothing **on the paths the draft actually holds**: those are that user's own pending answer to the same question and it is what they are looking at — every *other* moved path still applies, because one unsaved density click is not a reason for the tab to stop enforcing an auto-lock policy changed on the phone. The guard used to be global, and since `exitSettings` keeps a draft past the visit that made the tab deaf permanently and unrepairably: Save applies only the paths *it* drafted and Discard only the drafted look axes, so neither ever reached the adopted one. Both now drain what they own — Discard through the same live-apply Save uses, not just `applyLook` — and a path the incoming save *absorbed* (the drafted value is now the stored one) leaves the draft in the same tick and is applied, rather than stranding the app on the old value with neither button left to press.
- **Appearance previews; everything else waits for Save.** Theme, density and colour scheme repaint the moment they are picked — you cannot judge a theme from a label — while remaining ordinary draft entries that only Save persists. The preview deliberately does **not** write the `<head>` pre-paint cache: that cache predicts the *next boot*, and the next boot uses the stored value. Leaving the page with an unsaved appearance pick reverts the look (an unsaved theme must not be the look of a page you are not on); re-entering brings the draft *and* its preview back.
- **Leaving with an unsaved draft KEEPS it.** Back, a tree click, `⌘K`, the header's Back button and re-entry by `⌘/` / `⌘,` all behave identically, because they all funnel through `exitSettings`: the draft survives, a toast says how many changes are still unsaved, and the next visit paints them with Save still lit. Nothing is auto-reverted (that is the silent discard this exists to avoid) and nothing blocks a `popstate` with a modal (that is a page fighting the history stack). The one boundary the app does not own — a reload or a closed tab — is guarded by `beforeunload`.
- **Credentials and actions are not draft state.** The GitHub token and the AI key are **write-only**: the server serves a mask, so there is no current value to diff against and no reason to hold an unsaved secret — they `PUT` on change, as before, and never dirty Save. The same line excludes the terminal password (the server stores only a hash), the change-passphrase flow (it re-wraps `identity.age` in the crypto worker and touches no setting), and every **verb**: unlock, lock, sync now, run a command, generate a passphrase, re-probe the AI endpoint. A verb has no "before" to revert to. All of them keep working mid-draft, and a repaint one of them triggers must show the draft, not undo it.
- **The `Esc` stack, top to bottom**: modal veils (palette → shortcuts → passphrase → conflict → unsaved Raw exit → confirm) → context menu → session popover → an open inline tree editor (create/rename) → Raw editor to Preview (through the unsaved-change guard when dirty) → the mobile nav drawer → **the chat panel**. The chat is deliberately last, at every width: nothing above it loses its `Esc`. In the composer the first `Esc` blurs and the second closes the panel, so `Esc` mid-sentence costs a focus and not a surface — and the draft survives either way, because closing the panel collapses a grid column (or slides an overlay off-canvas) and never unmounts the textarea.
- **Home**: the vault button (top left) navigates to `editor.homeDoc` (default `index.md`; an extension-less value gets `.md`; blank means "the first doc"). A real navigation — one history entry, `Back` returns you. A home doc that does not exist is reported and offered for creation rather than silently ignored; cancelling opens the first doc, so the button is never inert. The dialog is the shared confirm, in its constructive tone — the warning glyph, red button and trash-retention footer belong to deletes, and a dialog whose OK button creates a file says what it actually does.
- No `type="password"` inputs anywhere (browser password-manager must stay out): masked fields are text + `-webkit-text-security` + `autocomplete="off"`.
- `.znotes/settings.toml` (committed): theme, density, color scheme, autosave seconds, home doc, trash retention days, branch, auto-sync, AI base URL/model/effort, terminal enabled/idle-lock/shell/starting directory/AI auto-run. sqlite (untracked): GitHub token, AI key, terminal password **hash**.

### 11. Testing gates

- **Round-trip**: golden corpus — open/save cycles byte-identical for externally-written files (frontmatter, setext, `1)` lists, tabs, trailing spaces).
- **Reconcile**: atomic-save simulation (temp+rename), identical-bytes suppression, burst debounce.
- **LIFO**: API-level — accept A,B; revert A → 409; revert B,A → byte-identical restoration.
- **Leak canary**: age armor never appears in AI relay payloads, logs, or search index; plaintext never in any server-bound request.
- **Parity**: computed-style/rect equality between modes across densities and breakpoints (port the prototype's headless checks) — one fixture per **shell band** (§9), not per padding rule, so a rule that reaches the document through `.app.chat-open` or through a fixed-overlay sibling is visible. The gate's own self-check — "these fixtures really are different layouts" — must reach **every** fixture, and it takes two measurements to do it, because `.doc` padding steps at 1150/767 and the shell steps at 1280/1024/768: the shell is asserted where the shell moves (`#scroll.x`) and the document where the document moves (padding). Mutation-tested: deleting the 768–1023 band outright used to leave the gate green with an identical `expect()` count. The narrow-phone fixture carries no distinctness claim — it is a second sample of the phone band, not a fifth band.
- **Measure floor**: with the assistant **open**, the document's text measure is ≥520px at every width that can afford it and ≥ the viewport minus its gutters below that, and the statusbar under it overflows by 0px with `#stConn` inside its own box — measured at 360/390/430/600/768/820/1024/1280/1440/1920. Parity proves the two modes agree; this proves what they agree on is readable. The remembered assistant state is asserted across a reload in the same gate, because a column a resize repaired but a reload broke again is not repaired.

- **Horizontal overflow is measured on `#scroll`, not on the page.** The document pane is the container that scrolls, and `document.documentElement.scrollWidth - clientWidth` is **0** while it overflows by 200+px — which is how a note containing a URL shipped scrolling sideways past every body-level sweep. One doc per construct (bare URL, unbreakable token, inline `code`, blockquote, list item, heading), at 360px, in all three themes and in both modes, asserting `#scroll.scrollWidth === #scroll.clientWidth`.
- **The phone's own affordances, at the sizes a thumb needs.** The chat composer tracks its content up to a cap (its `max-height` was unreachable text while nothing grew the field) and Send stays 44×44 inside the sheet; the sheet's top edge and head stay on screen with `--kb` set to what `wireVisualViewport` publishes, at 360×640/375×667/390×844/412×915, and the 440px cap is untouched with no keyboard; the tree row, the row context menu (item height *and* the distance between adjacent centres — "Rename / move" sits directly above "Delete") and the confirm's verbs are ≥44px, and the two bar-bound controls are hit-tested at their bar's top and bottom edge because `overflow: hidden` on a bar clips hit testing too. The tree long press opens the menu, does **not** open the doc under it, and does not fire on a drag or a short tap.
- **A corrupt index parks and the app still boots.** Swept over WHICH PAGE is damaged, not over whether damage is noticed: `Index.open` probes `sqlite_schema`, which reads page 1, so damage confined to a later page passed the probe and threw out of `migrate()` where nothing caught it — the server exited 1 with nothing parked. Page 1, later pages, a truncated tail and a non-database all boot, park exactly one file, and leave it the same length and still a sqlite file. Asserted through a real server process reaching its ready line, not only through the class.
- **The SSE watchdog keeps trying, and the middle state is rendered.** A black hole installed at the `EventSource` constructor (a stream that never opens and never errors — the exact boundary the recovery is written against) with the page's clock scaled so the 50s threshold and the 1→2→4→15s walk are reached in real seconds. A stuck reconnect is retried at least four times with never-shrinking gaps and never a 5s storm, the chip never says "connected" over it, and an open-but-silent stream renders "no signal" *before* the reconnect rather than having it written and replaced inside one task.
- **iOS zoom floor**: at 390px every text field in the document computes ≥16px, and the same probe at 1440px shows the floor has *not* leaked onto the desktop. It is a **sweep over every field actually mounted**, not a list of remembered ones — the failure is per-field and a field added later would reintroduce it silently — with the four the checklist names asserted by name afterwards so the gate cannot pass by finding none of them mounted.

### 13. Terminal

Deliberate, user-requested command execution on the user's own machine, in their own vault — a way to see, commit, sync and unwedge things without leaving the app.

**It is a streaming command runner, not a terminal emulator, and the UI says so.** Bun 1.3.14 has no PTY (`Bun.spawn(…, {pty:true})` is ignored; the child reports "not a tty") and node-pty is a native addon, which §1 forbids. So full-screen and interactive-editor programs — `vim`, `htop`, `less`, `git rebase -i`, `git commit` with no `-m` — are out of scope. The child gets `TERM=dumb`, `PAGER`/`GIT_PAGER=cat`, `NO_COLOR`, and a `GIT_EDITOR`/`GIT_SEQUENCE_EDITOR` that prints why it cannot open and exits non-zero, so the pager and the editor a tool *invokes* fail fast instead of blocking. A TUI the user invokes **directly** still just sits on stdin and has to be cancelled — so a run that has printed nothing for ten seconds says so in the scrollback rather than looking like progress.

- **The runner.** One command at a time — enforced at the point of execution, so the user's command, an approved command and the assistant's auto-run are all refused equally (`409 busy`) and the model can never displace what the user is running: `Bun.spawn([shell, "-lc", wrapper])` with stdout and stderr streamed live and separately tagged, the child's stdin writable (so a `y/N` prompt or a commit message still works — a write names the command it is for, so a stale client cannot type into a different one), and cancel = SIGTERM to the whole process subtree then SIGKILL after a grace. Output is capped at 2 MiB streamed (the pipe is still drained, so a chatty command cannot wedge) and 30 minutes wall-clock.
- **`cd` persists between commands.** The wrapper is `cd "$__ZNOTES_CWD_IN" || exit 1; <the user's command>` on line 1 — so the shell's own diagnostics carry the line number the user typed — then `__znotes_exit=$?; pwd > "$__ZNOTES_CWD_OUT" 2>/dev/null; exit $__znotes_exit` on line 2, where both paths are environment variables and `__ZNOTES_CWD_OUT` is a temp file outside the vault. The final `pwd` never touches stdout, so no sentinel has to be stripped and no output a command legitimately produced can be mistaken for one. A command that dies before that line keeps the previous cwd. The leading `cd` also survives a login shell whose profile does its own. The cwd is stored in sqlite `meta`, so it survives a restart.
- **Auth.** A dedicated terminal password, **independent of the vault passphrase** — that one is client-side only and the server never sees it, so it structurally cannot gate a server feature. Only `scrypt$logN$r$p$salt$hash` (logN=17, r=8, p=1 — the vault's KDF one notch down, because this one runs server-side where memory cost is also a DoS) lives in sqlite `credentials`, masked-by-absence in `GET /api/settings` (`terminal.passwordSet: true|false`). Unlock mints a random 32-byte **bearer** token held in api.js memory only — not a cookie, because a cookie is ambient authority the browser attaches to every same-origin request; not persisted, so a reload re-locks. Idle timeout (`terminal.idleLockMinutes`) plus a 12-hour ceiling. **No password ⇒ the terminal is disabled and says so; it is never default-open.**
- **Failure modes.** Wrong password: constant-time compare, and a full decoy derivation when no password is set — built off the request path, so the FIRST attempt costs the same either way and `POST /api/terminal/unlock` is not an oracle for whether one exists in its timing any more than in its wording. Three free attempts, then exponential backoff to 60 s (429 with `retryAfterMs`), counted per calling address: a limiter on one global counter is one peer away from being a lockout for everyone else. Changing an existing password requires the current one or a live session. `settings.toml` can carry `[terminal] password = "…"` to bootstrap a fresh install — absorbed, hashed, stripped from the file, never committed — and is **ignored and stripped** if one is already set, so a synced file cannot take the terminal. The password never appears in a response, a log line, an SSE payload or the settings object; command output is never written to the vault or to git, and a transcript that contains age armor is withheld from the durable record entirely — it would otherwise put armor in sqlite (§11) and, being replayed into every later context, would make the relay's canary refuse every subsequent turn.
- **UI.** A Terminal section on the Settings page (`/settings/terminal` — §9), in the existing chrome: lock state row, password field, unlock, the settings, then the console — cwd, monospace scrollback, prompt with ↑/↓ history, Ctrl+C to cancel, Ctrl+D for EOF, Ctrl+L to clear. Stop and Ctrl+C follow the SERVER's `running`, so a command another tab or the assistant started can be cancelled from here too — the refusal that names Ctrl+C is never a dead end. No `type="password"` anywhere (§9): text + `.masked`. ANSI is stripped rather than half-rendered — statefully per stream, so an escape split across two chunks is still an escape.
- **AI access** — see §8 for the tool and the gate.
